title: 安全基线
---

## 服务端入口

`src/server.ts` 在每个动态请求前执行环境校验，并通过 `src/lib/security-headers.ts` 添加 CSP、`X-Content-Type-Options`、Referrer Policy 等响应头。`server/serve.mjs` 保留多个 `Set-Cookie` 响应头，避免认证 Cookie 被合并。

## 环境

- `BETTER_AUTH_SECRET` 至少 32 个字符。
- `BETTER_AUTH_URL` 必须是绝对 URL，生产使用 HTTPS。
- `DATABASE_URL` 必须指向 PostgreSQL。
- OAuth、Turnstile 必须成对配置；Stripe key 必须配 webhook secret。

## 竞猜匿名身份

参与者 ID 由服务端生成，只保存在 HttpOnly、SameSite=Lax Cookie，不会通过 loader 或公开提名数据返回。提名和投票仍不要求登录，因此主动清 Cookie 的重复参与无法仅靠 Cookie 解决；正式活动应增加登录、Turnstile、活动级限流或其他可信身份策略。

## 输入与授权

- 提名、封面 URL、搜索、评分和评论必须通过服务端校验。
- 管理员和所有权检查必须在 server function/领域服务执行。
- 文件对象 key 必须通过路径穿越检查。
- 数据库测试不得连接共享或生产数据库。
